# 项目难点与决策（STAR 故事）

> 用途：面试被问"讲一个你解决过的难点"时使用。每个故事按 **情境 → 任务 → 行动 → 结果** 组织，
> 均可对应项目中的真实代码与评估数据。挑 3 个讲熟，不要五个都讲。

## 故事 1：数据驱动的功能取舍（查询改写默认关）

- **情境**：检索质量遇到"口语查询 × 书面文档"的语义鸿沟，想引入查询改写（规则 / LLM 两档）。
- **任务**：决定是否默认开启，并保证不因改写丢失精确信息。
- **行动**：建 A/B 评估（同一 GT、同一检索管线，只切改写档）；发现检索侧无增益、端到端甚至微降；设计"双路兜底"（原 query + 改写结果都检索）与"精确词豁免"（含数字/型号/英文专名跳过 LLM 改写）。
- **结果**：**改写默认关**，触发式启用；评估数据与保护机制都沉淀在文档里（EXPERIMENTS.md）。面试话术：**"功能不是拍脑袋加，而是用评估数据决定要不要，以及怎么加才不伤基线。"**

## 故事 2：跨库一致性（幽灵向量与对账自愈）

- **情境**：文档重摄入/删除后，Milvus 里出现"PG 已删但向量还在"的幽灵，污染 top-K 检索（实测累积 192 条）。
- **任务**：建立可自愈的一致性机制，而不是"双写双删"这种脆皮方案。
- **行动**：把 Postgres 定义为**事实源**、Milvus 定义为**派生索引**：写入先落 PG（`vector_status=pending`）→ 幂等同步 Milvus → 标记 synced；删除先删事实源；后台 `reconcile_vectors` 对账任务做双向 diff（幽灵 doc_id 删除、缺失块补写）。
- **结果**：增量摄入失败不再依赖补偿删除，由对账任务兜底；测试也加"删除收敛等待"，防止幽灵再次累积。面试话术：**"一致性靠'事实源 + 对账'而不是'双写'，因为后者在失败时没有单一真相。"**

## 故事 3：评估体系本身也需要工程化

- **情境**：用 LLM-as-judge 评估 RAG，发现指标与直觉不符——faithfulness/recall 系统性偏低，relevancy 对对比、筛选、否定型问题误判。
- **任务**：让评估结果可信，才能用它驱动决策。
- **行动**：三轮校准——(1) judge 输入截断 400→800 字符，修复块后半段关键句被裁导致召回/忠实度低估 8~11pp；(2) relevancy 评分指引（0/1/2 分级语义）修复误判，Rel 0.885→1.0；(3) NDCG 评估改走生产同路径（rerank/去重/限流全开），发现排序层真实瓶颈。
- **结果**：四指标闭环进 CI，成为后续所有实验的"裁判"。面试话术：**"被评估系统和评估体系都要工程化——指标不准，后面所有优化都是空中楼阁。"**

## 故事 4：流式体验（打字机效果的去重与防碎片）

- **情境**：SSE 流式下，LLM 工具调用前会输出开场白（"我来帮您…"），工具后又把开场白连同答案重新生成，导致"碎片感"和重复前缀。
- **任务**：让前端体验像真打字机，又不能丢信息。
- **行动**：三件事——(1) 开场白缓冲：工具触发前不逐字显示，超过 40 字符阈值判定为直接回答再开始流式；(2) `_PreludeDedupe` 前缀去重：工具后跳过重复开场白；(3) 注册工具集合过滤：模型幻觉吐未注册工具的 tool_call 不点亮工具轨道。
- **结果**：流式输出平滑无碎片、无重复；这套逻辑有专门单测（`test_stream_dedupe.py`）覆盖各种切割场景。面试话术：**"体验问题背后是状态机时序问题，我把'何时显示'做成了确定性规则而不是靠模型自觉。"**

## 故事 5：把核心能力抽成可独立运行的包（task-agent）

- **情境**：长任务 Agent（replan / HITL / verify / Time Travel）在宿主应用里，代码与业务耦合，没法独立演示或复用。
- **任务**：拆成"简历可讲、可独立运行"的包，且不影响宿主 API。
- **行动**：抽到仓库顶层 `task-agent/`（src 布局、零 `app.*` 依赖）；设计四个接口缝（配置 / LLM 工厂 / Checkpointer 提供者 / 每步执行器），宿主用适配器注入现有能力；包内自带脚本化 FakeLLM 离线 demo 与 50 个单测。
- **结果**：`python -m task_agent.demo` 离线跑通 目标→replan→execute→check→final 全流程；真实 LLM 只需配环境变量；宿主 `/api/agent-tasks/*` 接口不变。面试话术：**"把系统里最难的部分做成可插拔、可离线验证的独立包，是抽象能力的最直接证明。"**

## 备选：安全与多租户（加分项）

- Prompt 注入防护（外部内容隔离包装 + 规则检测分层）、多用户知识库/记忆隔离、MCP 只读 SQL 校验（连接层 `default_transaction_read_only` + sqlparse 白名单 + 系统目录拦截）、数据所有权（注销账号全链路清理）。讲到数据/安全问题时抛出，面试官一般会追问。
