# 系统设计面试话术：从零设计一个 RAG 客服系统

> 用途：面试官让你"设计一个基于企业知识库的问答系统"时的答题框架。
> 每一步都对应本项目真实实现，能当场引用代码路径。

## 一、需求澄清（先问再设计）

1. **数据**：文档类型（PDF/DOCX/网页/表格/图片？）、数量级（100 份 / 1 万份？）、更新频率（月度 / 实时？）
2. **场景**：单轮问答还是多轮对话？是否需要引用溯源？是否允许联网？
3. **质量与成本**：期望准确率（决定是否上 rerank / 大模型）、预算（每问成本上限）
4. **安全**：多租户？是否需要权限隔离、内容过滤？

> 话术："我会先确认数据规模和更新频率，因为它们直接决定分块策略和摄入架构；再确认质量要求，因为它决定评估闭环怎么建。"

## 二、架构（数据流）

```
文档摄入：解析（文本/表格/图片）→ 分块（Markdown 标题/按页/表头感知）→ 嵌入 → 向量库
           元数据（事实源）落关系库，块指纹做增量去重

在线检索：query → 改写(可选) → 混合检索（向量 + BM25 + RRF）→ rerank 精排
           → 上下文压缩（去重/合并/预算）→ 组装 prompt → LLM 生成 → 引用溯源

评估闭环：GT 数据集 → LLM-as-judge 四指标（Precision/Recall/Faithfulness/Relevancy）
           → 每次改检索参数先过回归，再决定上线
```

## 三、关键决策点（每个都能展开 1-2 分钟）

### 1. 分块
- 纯长度切分丢语义边界 → 本项目：中文按句号/感叹号分隔 + 10~20% 重叠，Markdown 按标题层级切分（块自带章节上下文），表格按"表头 + N 行"行列感知切块。
- 关键点：**分块策略随文档类型分化，并用评估集调参**。

### 2. 为什么混合检索（向量 + BM25 + RRF）
- 向量抓"语义相同、字面不同"，关键词抓专名/型号/数字；RRF 无参融合比加权求和稳。
- 关键词通道用内存 BM25（进程内索引 + 签名 TTL 失效），不引入 Elasticsearch。

### 3. 为什么 rerank 放最后、候选必须限流
- Bi-Encoder 快但丢交互，Cross-Encoder 准但贵 → "宽召回、少精排"，候选数 `rerank_candidate_k` 限流，控制 CPU 推理量。

### 4. 增量摄入与一致性
- 内容指纹（sha256）→ 相同块不重嵌入；Postgres 事实源 + Milvus 派生索引 + 对账任务自愈。
- 摄入中检索：签名 TTL + 主动失效，秒级最终一致。

### 5. 评估闭环（差异化亮点）
- 自建 LLM-as-judge（对齐 RAGAS 口径）：Context Precision / Recall / Faithfulness / Answer Relevancy。
- judge 与生成器分开实例（temperature=0 + JSON mode 固定格式）。
- 三层指标互补：Hit@K（检索命中）→ NDCG（排序）→ 四指标（端到端）。
- **铁律：评估必须复现生产管线**（rerank/去重/限流都开），否则指标失真。

### 6. 成本与延迟
- 成本 = 输入 token（检索块 + prompt）× 单价 + 输出 token × 单价 + rerank 推理成本。
- 优化手段：块预算（`rag_max_total_chars`）、rerank 候选限流、改写默认关、轻量子 Agent 模型。
- 延迟分解：检索 p50 ~82ms；瓶颈在 LLM 生成（SSE 首 token ~19ms）。

### 7. 安全与隔离
- Prompt 注入：外部内容"隔离包装 + 规则检测"分层；多租户：user_id 隔离知识库/记忆/会话；
- MCP 只读：连接层强制 read-only + statement_timeout，sqlparse 白名单 + 系统目录拦截。

## 四、扩展路径（展示边界意识）

- 单机够用（~16 QPS）：先量化触发信号再升级（多 worker：任务落库、缓存 Redis、BM25 每 worker 重建；多副本：会话亲和、外部队列）。
- 强一致可加块版本号；更大规模可换专用向量库/分片。

## 五、选型话术（"为什么不用现成的"）

### 为什么 LangGraph 而不是自己写状态机？
> "多 Agent 编排本质是带持久化/回滚/中断的状态机，自己写容易在 HITL 恢复、时间旅行这些边界上出错。LangGraph 提供 interrupt/Command/checkpointer 原生机制，我负责业务语义（哪些步骤要确认、失败怎么降级），框架负责状态正确性。"

### 为什么不用 LlamaIndex？
> "LlamaIndex 偏'拿来即用'的检索链路，但我需要精细控制管线（混合检索权重、rerank 候选、上下文压缩、多轮改写）并用自有评估逐项验证——自建管线（LangChain 组件组合）让每一步都可观测、可 A/B。"

### 为什么自建 LLM-judge 而不是直接用 RAGAS？
> "RAGAS 是黑盒，出问题不知道是 prompt 还是指标公式；自建后我能校准（截断长度、评分指引），并把四指标闭环进 CI。校准本身发现并修复了真实缺陷——评估体系也是要工程化的。"

### 为什么向量库用 Milvus 而不是 pgvector？
> "项目评估与检索要走独立、高性能的向量索引（HNSW），Milvus 便于水平扩展和标量过滤组合；pgvector 用于 LangGraph 长期记忆的语义索引，各取所长。"
